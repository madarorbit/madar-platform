# مَدار للهاتف — MADAR Dashboard V2.0

تطوير مباشر لتطبيق V1 داخل مشروع Expo نفسه. يستخدم حساب مَدار ومساحات العمل وORBY Core وMADAR Connect ومحرك الاستحقاقات القائمة؛ لا ينشئ نظامًا أو مسار بيانات موازيًا.

## ما يقدمه V2

- تسجيل الدخول بجلسة Supabase نفسها مع Bearer token وRLS لكل مساحة.
- تعدد مساحات العمل مع ذاكرة تخزين منفصلة لكل مساحة ومنع خلط البيانات.
- لوحة رئيسية وتقارير ومصطلحات تتكيف مع التجارة أو المطعم أو الفندق.
- عرض مصدر الحقيقة، صحة الموصل، حداثة المزامنة والصلاحيات الفعلية.
- محادثات أوربي المشتركة بين المنصة والهاتف: Threads، استعادة السجل، بث SSE، إيقاف، إعادة، مراحل تشغيلية واستشهادات البيانات.
- عمليات يومية محددة فقط: حالة مهمة، تذكرة مطبخ أو مهمة تنظيف.
- كل كتابة تمر عبر الخادم: استحقاق ودور وصلاحية موصل → معاينة منتهية الصلاحية → تأكيد صريح لمرة واحدة → كشف تعارض → تنفيذ داخل مَدار أو صف MADAR Connect → تحقق وسجل تدقيق.
- تحديث عند عودة التطبيق للمقدمة، Realtime للأحداث المتاحة، وتحديث احتياطي دوري.
- وضع فاتح وداكن أو حسب الجهاز، RTL، حالات تحميل/فراغ/خطأ، ودعم أساسي لإمكانية الوصول.
- نسخة محلية للقراءة عند انقطاع الشبكة؛ لا تُنفذ الكتابات أثناء عدم الاتصال.

## التشغيل والتحقق

```bash
cd mobile
cp .env.example .env
npm ci
npm run typecheck
npm run export:android
npm start
```

متغيرات `EXPO_PUBLIC_*` عامة بطبيعتها. لا تضف `SUPABASE_SERVICE_ROLE_KEY` أو مفاتيح الموصلات أو مزودي أوربي إلى التطبيق. مفتاح Supabase في التطبيق Publishable فقط، بينما الحماية الفعلية في المصادقة وRLS وعقود RPC الخادمية.

## عقود الخادم

- `GET /api/mobile/v1/dashboard`: Snapshot قطاعي، المساحات، الباقة، الاستحقاقات، المزامنة والقدرات المسموحة.
- `GET|POST /api/mobile/v2/actions`: سجل الإجراءات وإنشاء معاينة كتابة آمنة.
- `POST /api/mobile/v2/actions/:id`: رفض أو تأكيد المعاينة.
- `GET /api/orby/conversations` و`GET /api/orby/conversations/:id`: سجل المحادثات المشترك.
- `POST /api/orby/stream`: بث أوربي من ORBY Core ببروتوكول SSE الموحد نفسه المستخدم في المنصة.
- مسارات `api/orby/agent/*`: تقبل جلسة الويب أو Bearer token من التطبيق، مع الصلاحيات نفسها.

يتطلب مسار الإجراءات تطبيق migration `20260810090000_madar_dashboard_v2.sql` في بيئة الترحيل المعتمدة. لا يطبق التطبيق migrations بنفسه.

## APK ونسخة المتجر

`eas.json` يحافظ على ملف `preview` لإنتاج APK داخلي، و`production` لإنتاج إصدار متجر بتوقيع دائم. لا تنشر النسخة أو تطبق migration من جهاز المطور؛ يمر ذلك عبر مسار الإصدار والمراجعة المعتمدين.
