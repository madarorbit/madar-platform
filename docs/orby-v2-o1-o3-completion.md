# ORBY V2.0 — إغلاق المراحل O1–O3

**الفرع المرجعي:** `codex/madar-v2-p0-p11-foundation`  
**الموقع في الخطة:** القسم الثاني من خطة مَدار V2.0، مبني فوق القسم الأول ومحرك الربط وUDM والصلاحيات.  
**الحالة:** مكتمل برمجيًا على مستوى العقود والنواة والواجهة ومحرك الحوار، ولا يتضمن دمجًا إلى `main`.

## O1 — توحيد نواة أوربي وفصل المزودات

- جميع مسارات المحادثة الحالية تمر عبر `createServerOrbyFoundation` ثم `OrbyKernel.execute` أو `OrbyKernel.stream`.
- المزودات لا تُنشأ داخل واجهة المحادثة أو مسارات API؛ تُحمّل فقط من `src/lib/orby/providers` من متغيرات الخادم.
- `Provider Interface` و`Provider Registry` و`Model Registry` وRouting/Fallback وHealth وCircuit-safe retry موجودة داخل النواة.
- `Prompt Compiler` يبني التعليمات خارج الواجهة من السياسات والسياق والتاريخ والرسالة.
- دستور الشخصية أصبح طبقة مستقلة وذات إصدار، ويُرسل إلى النواة كسياسات نظام لا كتعليمات مكتوبة داخل الواجهة.
- الجلسات مربوطة بالمؤسسة والمستخدم ومساحة العمل، مع منع صريح للوصول إلى جلسة تخص نطاقًا آخر.
- السياق يمر بميزانية أحرف، وأولوية مصادر، وحدود تمنع تمرير ما لا يحتاجه الطلب.
- القدرات الجديدة `conversation-v2` و`personality-engine` و`intent-dialogue` مسجلة في Capability Registry.

## O2 — واجهة المحادثة الحديثة

- بروتوكول محادثة موحد بإصدار `2.0.0` للرسائل النصية والاستشهادات والأدوات والموافقات والنتائج.
- مسار بث SSE: `POST /api/orby/stream`، ويستخدم `ORBY Core` نفسه ولا يستدعي المزود مباشرة.
- حالات تشغيل مسموح بعرضها: استلام الطلب، مراجعة السياق، اختيار المسار، تجهيز الرد، الحفظ، الاكتمال.
- لا تُعرض سلسلة التفكير الداخلية.
- الواجهة تدعم البث التدريجي، الإيقاف، إعادة المحاولة، إعادة التوليد، النسخ، تعديل رسالة المستخدم وإعادة إرسالها، وتقييمًا محليًا للرد.
- الإرسال بـEnter والسطر الجديد بـShift+Enter، مع تكبير تلقائي لمربع الكتابة و`aria-live` للحالة.
- الاستشهاد يوضح المصدر، حداثة البيانات، وما إذا كانت مؤكدة أو تقديرية.
- أي طلب يُصنف ككتابة يعرض تنبيه معاينة واضحًا، ولا يعتبر الرد نفسه إذن تنفيذ.
- المحادثات القديمة تستمر عبر `kernel_session_id` مع توافق رجعي مع جداول أوربي V1.0.

## O3 — شخصية أوربي ومحرك الحوار

- دستور أوربي المعتمد محفوظ في `src/lib/orby/personality/constitution.ts` بإصدار `2.0.0`.
- الهوية تابعة لمَدار ولا تُنسب إلى OpenRouter أو OpenAI أو Gemini أو Claude أو أي نموذج.
- الدستور يعرف أوربي بأنه المساعد الرسمي لمَدار المطور ضمن رؤية مؤسسها ومدير فريقها، المدير إدريس بن عارف.
- Intent Engine يميز بين السؤال المعلوماتي، التحليل، التقرير، الخطة، التنفيذ، والمراقبة المستقبلية.
- كل طلب يحصل على تصنيف قراءة/كتابة/مراقبة، قطاع، حساسية، درجة ثقة، واستراتيجية رد.
- Dialogue Manager لا يطلب توضيحًا إلا عند نقص هدف الكتابة أو غياب سياق التحليل المطلوب.
- Sector Terminology يعزل التجارة والمطاعم والفنادق والطالب/الشخصي ويمنع خلط المصطلحات.
- الشخصية والسياسات حتمية ومستقلة عن النموذج؛ تبديل المزود لا يغير دستور أوربي أو استراتيجية الحوار.

## بوابة القبول

الأمر:

```bash
npm run orby:v2-o1-o3
```

ويثبت:

1. ملكية مَدار للدستور وهوية أوربي.
2. التمييز بين سؤال معلوماتي وطلب تنفيذ.
3. ثبات الشخصية عند تبديل النموذج.
4. عزل مصطلحات التجارة والمطاعم والفنادق.
5. تسجيل قدرات O1–O3 في النواة.
6. مرور التنفيذ والبث عبر ORBY Core فقط.
7. عدم وجود استدعاء مباشر للمزود داخل مسارات المحادثة.
8. نجاح دورة البث والإيقاف وإعادة المحاولة والنسخ والتعديل والاستشهاد.
9. منع بناء الدستور أو Prompt داخل مكوّن الواجهة.

## حدود الإطلاق

- التنفيذ الحساس لا يزال خاضعًا لطبقة O4 والموافقة والتحقق والتدقيق.
- قنوات خارجية مثل واتساب لا تُربط مباشرة بالنواة.
- مفاتيح المزودات تبقى في متغيرات الخادم ولا تُحفظ في الكود أو قاعدة بيانات المحادثة.
